SBIR Phase II — Outline Sketch

From Classical Phase Retrieval to Quantum-Extended Sensing

A technical bridge from the funded Phase I dispersion-assisted GS phase-recovery work to a quantum-sensing Phase II, built on capability that already exists in this repository — not a pivot into a new field.

Phase I: $275K, 3 investigators Phase II (illustrative): $1.75M OUSD CTA: Quantum Science · Integrated Sensing and Cyber

01The One-Sentence Thesis

Phase I proved that dispersion can be used to recover phase from intensity-only measurements in a classical photonic receiver. The identical mathematical problem — recovering phase from a measurement that only gives you magnitude — is the central bottleneck in quantum photonic sensing and quantum key distribution. Phase II doesn't change the problem; it changes which photons are counting.

02What Phase I Actually Proved

Proven, verified this cycle

  • Dispersion-assisted Gerchberg-Saxton (GS) phase retrieval, cross-validated against a Fourier Neural Operator that independently rediscovers the same closed-form dispersion kernel H(f)=exp(iπDf²)
  • Real Mie-scattering hardware validation (CUDA-accelerated, cross-checked against an independent Python reimplementation)
  • Kramers-Kronig causality as an external certificate for phase-retrieval ambiguity — confirmed structural (not a one-off bug) across 200 Monte Carlo trials
  • A characterized failure mode: GS's own convergence metric can be fooled; causality catches what the algorithm's own error metric cannot

What this hands to Phase II

  • A validated dispersion-encoding technique for phase recovery
  • A working ambiguity-detection method (causality-as-certificate) that generalizes past classical GS to any phase-recovery pipeline, quantum ones included
  • An FNO-based learned-operator toolchain already shown to rediscover a known physical kernel from data alone
  • Real hardware-in-the-loop validation discipline (not simulation-only claims)

03Three Candidate Technical Thrusts

Ranked by how directly each one reuses Phase I infrastructure versus requiring new capability. All three are grounded in modules that already exist in this repository, not proposed from scratch.

Lowest new-capability risk

Thrust A — Causality-Certified Quantum Phase Estimation

Quantum phase estimation (the core primitive behind quantum sensing and quantum computing's own Shor's-algorithm-class routines) faces the same ambiguity problem Phase I's KK-certificate work already characterized: a phase-estimation circuit can converge to a self-consistent but physically wrong answer. Extend the causality-certificate methodology from classical dispersion to quantum phase-estimation circuits as an independent validation layer.

Grounded in
dgs/causality.py · notebooks/kk_phase_retrieval_certificate.ipynb · notebooks/kk_certificate_monte_carlo.ipynb · dgs/quantum_modulo.py (existing QPE simulation)
Direct hardware extension

Thrust B — Dispersion-Assisted Quantum Receiver for QKD

Phase I's dispersion-encoding trick, applied to a real BB84 optical link: use dispersion as a passive, low-cost way to add a phase-based side channel to an existing polarization-based QKD receiver, potentially improving key rate or adding an eavesdropping-detection signature beyond the standard intercept-resend statistics.

Grounded in
dgs/photonic_qkd.py (BB84 via real Jones-calculus optics, not a toy coin-flip model) · dgs/gs_core.py
Systems / link-budget

Thrust C — Quantum Internet Repeater-Node Sensing

Quantum repeater nodes need to characterize link quality (loss, timing jitter, phase noise) without destroying the quantum state in transit. Adapt the dispersion-assisted phase-recovery approach as a classical side-channel diagnostic riding alongside the quantum channel — measuring the classical carrier's phase to infer link health without touching the qubits.

Grounded in
dgs/quantum_internet_link_budget.py (fiber vs. satellite link budgets, entangled-pair detection rates, repeater spacing) · dgs/gs_fno.py

06Risk and the Honest Tradeoff

Staying purely classical (deepening the GS/dispersion work) is lower-risk and faster to publish — it's an area with demonstrated, deep expertise now. Going quantum is a real lift: different noise model (shot-noise-limited single photons, not classical intensity), different hardware (single-photon detectors, not a photodiode), and a genuinely harder validation story. The case for taking that risk is that Quantum Science is where a meaningful share of OUSD funding actually sits, and Thrust A specifically costs almost nothing to attempt first — it's a software extension of an existing simulation module, not a hardware bet — making it a reasonable way to test the quantum direction before committing Phase II's full budget to it.

Suggested next concrete step
If any of this is worth pursuing for real, the lowest-cost next step is prototyping Thrust A — extending notebooks/kk_certificate_monte_carlo.ipynb's statistical methodology to dgs/quantum_modulo.py's QPE simulation. That's a notebook, not a hardware commitment, and would give a concrete result to put in front of a program manager before writing the full proposal.
